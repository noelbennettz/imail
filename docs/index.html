A mail server, not a stack of services.

One process serves the protocols, the mailbox and the admin console.

One binary, embedded UI

The Go server embeds the Vue 3 web client and the Inter font. No nginx, PHP, Node or external asset CDN in production; the image needs one process.

The whole mail stack

SMTP on 25 with STARTTLS, submission on 587, SMTPS on 465, IMAPS on 993, POP3 on 110 with required STLS, and POP3S on 995.

A real web mailbox

Material 3, light/dark/system themes, search, conversation grouping, reply, reply-all, forward and attachments. Seven UI languages, selected from the browser.

Domains, users and quotas

A primary domain plus additional domains, per-domain users, per-mailbox quotas, and an admin console for domains, users, DNS and certificates.

Certificates handled

ACME with HTTP-01, manual DNS-01 or automatic Cloudflare DNS-01; uploaded certificates too. Each domain can carry its own cert, and renewals run daily.

Deliverability built in

DKIM signing, SPF checks, DMARC and PTR guidance in the setup wizard, and a configurable spam-filter level. Outbound delivery verifies the remote MX certificate.

IPv4 and IPv6, independently

listenMode and egressMode choose the family for listeners and outbound delivery. A configured family the host lacks falls back to the other one at startup.

A backup is a directory

SQLite by default, with MySQL and PostgreSQL for larger deployments. Configuration, database, DKIM key and certificates all live under config/.

Deploy on a VPS

Docker with Compose, a public IPv4 and/or IPv6 address, and a domain whose DNS you control. Port 80 must be reachable for HTTP-01.

Clone and create the data directory

The config/ directory is the whole server state: configuration, SQLite, DKIM key and TLS material.

git clone https://github.com/noelbennettz/imail.git
cd imail
mkdir -p config

Start the published image

This pulls ghcr.io/noelbennettz/imail:latest and publishes the eight mail and web ports.

docker compose -f docker-compose.ghcr.yml up -d
docker compose -f docker-compose.ghcr.yml logs -f imail

Finish the setup wizard

Open http://your-server-ip/: database, administrator, domains, DNS records and TLS. The wizard disappears after the first successful init, so finish it on a trusted network.

Check port 25 before debugging anything else. Many VPS providers block outbound TCP 25; receiving works, but delivery to other mail servers does not until they lift it. On rootless Docker, publish high host ports instead (8080:80, 18443:443, …) because ports below 1024 cannot be bound.

DNS and TLS, generated for you

The setup wizard writes the exact records for every domain. This is the shape of them.

  • A and AAAA for the mail host. Add both families if the server has both; add MX, SPF, DKIM and DMARC for every domain that receives mail.
  • PTR is set at the VPS, not in your zone. Point reverse DNS at smtp.example.com so receivers can confirm the sending host.
  • TLS covers every hostname clients use. Usually the apex plus smtp., imap., pop. and the web domain.
  • Three certificate flows. HTTP-01, DNS-01 (manual or Cloudflare token) and upload. Per-domain certificates are selected by SNI; HTTP-01 and Cloudflare renew automatically.
@                  A/AAAA  203.0.113.10 / 2001:db8::10
mail               A/AAAA  same address
smtp               A/AAAA  same address
@                  MX      10 smtp.example.com.
@                  TXT     "v=spf1 a mx ~all"
default._domainkey TXT     "<from the setup wizard>"
_dmarc             TXT     "v=DMARC1; p=quarantine; rua=mailto:postmaster@example.com"

Propagation takes longer than the wizard. Check with dig +short MX example.com, the DKIM TXT record, _dmarc, and dig -x <server-ip> before blaming the server.

IPv4 and IPv6 are separate decisions

One setting for listeners, one for outbound delivery, and a sane fallback when the host only has one family.

  • listenMode: both, ipv4 or ipv6. both uses Go's dual-stack wildcard, so one socket serves both families.
  • egressMode chooses the outbound family. In both mode delivery uses Happy Eyeballs: an AAAA-only destination goes over IPv6, an A-only one over IPv4.
  • A missing family is detected at startup. If the configured family does not exist on the host, iMail logs a warning and uses the other one instead.
  • Health checks follow the same result. They probe both loopbacks, so an IPv6-only container is not reported unhealthy for ignoring 127.0.0.1.
"listenMode": "both",
"egressMode": "both"

No wildcard guessing. The wizard's A/AAAA guidance and the public-address probe are family-specific, so an IPv6 address is never printed as if it were IPv4 (or the other way round).

Mail-server defaults that do not cut corners

Passwords, TLS and the setup window are the three things that matter most.

Passwords and sessions

PBKDF2-HMAC-SHA256 with 210,000 iterations, a minimum of eight characters, and every existing session revoked when a password changes. Old MD5 hashes are upgraded on the next successful login.

TLS is not optional

TLS 1.2 and 1.3 only, strict SNI by default, IMAP never exposed without TLS, and outbound delivery fails instead of silently falling back to plaintext when the MX certificate cannot be verified.

Secrets stay in one place

config/config.json is written with mode 0600; the DKIM private key and TLS keys live under config/. Back it up, never commit it, and finish the setup wizard before exposing the host.

Questions

The things worth knowing before pointing MX records at a new host.

Is this a mail server or just a webmail client?

Both. iMail speaks SMTP, submission, SMTPS, IMAPS, POP3/STLS and POP3S itself, and also serves a browser mailbox and an admin console. Any standard mail client can connect; the web UI is not required for day-to-day mail.

My VPS blocks port 25. Can I still use it?

You can receive on alternate ports if your provider supports that, but sending directly to other mail servers needs outbound TCP 25. Ask the provider to unblock it or configure a relay yourself; iMail does not hide a blocked port behind a generic timeout.

How does login work with multiple domains?

With one domain, alice and alice@example.com both work. With two or more, the full address is required because the bare name would be ambiguous. Accounts are globally unique: alice@one.example and alice@two.example cannot coexist; name them alice and alice-sales.

Do I have to use its ACME certificates?

No. HTTP-01, manual DNS-01, Cloudflare DNS-01 and uploaded PEM certificates are all supported, globally or per domain. Automatic renewal applies to the two ACME flows; watch uploaded certificates yourself.

Can it run behind a TLS reverse proxy?

Yes. Set httpsEnabled to 2 for HTTP-only mode and let the proxy terminate TLS. Session cookies only get Secure when HTTPS is enabled, so the proxy must be trusted.

What do I back up?

The whole config/ directory: config.json, the SQLite database (or your DSN), the DKIM private key and the certificate directory. Copy it to a new host and the server comes back as it was.

Does it work on an IPv6-only or IPv4-only host?

Yes. listenMode and egressMode are independent, and a configured family that is missing at startup falls back to the other one with a warning. Delivery to a dual-stack destination uses Happy Eyeballs.

Why AGPL?

Self-hosting, forking and paid support are fine. If you run a modified iMail as a network service, its users must be able to get the source of the version you run; that is section 13.

iMail is a self-hosted mail server for your own domains. One Go binary, an embedded Vue 3 client, and no external services at runtime.
