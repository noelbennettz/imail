是一台郵件伺服器，不是一堆服務的堆疊。

同一個行程提供協定、信箱與管理台。

單一 binary，前端內嵌

Go 伺服器把 Vue 3 前端與 Inter 字型一起包進去。production 不需要 nginx、PHP、Node 或外部 CDN，image 只跑一個行程。

完整郵件協定

25 的 SMTP（STARTTLS）、587 submission、465 SMTPS、993 IMAPS、110 POP3（認證前必須 STLS）與 995 POP3S，全部自己處理。

真的能用的網頁信箱

Material 3、淺色／深色／跟隨系統、搜尋、對話群組、回覆、全部回覆、轉寄與附件下載。七種介面語言依瀏覽器自動選擇。

多網域、使用者與配額

主要網域加多個附屬網域、各網域自己的使用者、每個信箱的配額，以及管理網域、使用者、DNS 與憑證的管理台。

憑證不用自己盯

支援 HTTP-01、手動 DNS-01、Cloudflare DNS-01 與上傳憑證；每個網域可以有自己的憑證，ACME 憑證每天檢查、剩 30 天內自動續。

送信信譽內建

DKIM 簽章、SPF 檢查、安裝精靈提供 DMARC 與 PTR 指引，外加可調的垃圾郵件等級。外送時會驗證對方 MX 的憑證，不偷偷退回明文。

IPv4 與 IPv6 分開決定

listenMode 管監聽、egressMode 管外送；啟動時發現設定的位址族不存在，會記警告並降級到另一族。

備份就是複製目錄

預設 SQLite，較大的部署可用 MySQL 或 PostgreSQL。設定、資料庫、DKIM 私鑰與憑證全在 config/ 底下。

部署到 VPS

需要 Docker + Compose、一個 public IPv4 和／或 IPv6，以及你自己控制 DNS 的網域。HTTP-01 需要對外開放 80。

抓原始碼並建立資料目錄

config/ 就是整台伺服器的狀態：設定、SQLite、DKIM 私鑰與 TLS 材料。

git clone https://github.com/noelbennettz/imail.git
cd imail
mkdir -p config

啟動已發佈的 image

這會拉 ghcr.io/noelbennettz/imail:latest，並發佈八個郵件與網頁 port。

docker compose -f docker-compose.ghcr.yml up -d
docker compose -f docker-compose.ghcr.yml logs -f imail

完成安裝精靈

開 http://your-server-ip/：資料庫、管理員、網域、DNS 紀錄與 TLS。第一次初始化成功後精靈就會消失，請先在可信網路完成。

先確認 25 port，再開始除錯。很多 VPS 擋 outbound TCP 25；收信可以，但要寄到其他郵件伺服器就得請供應商解鎖。 Rootless Docker 不能綁 1024 以下，請改成高埠映射（8080:80、18443:443…）。

DNS 與 TLS，精靈幫你產生

安裝精靈會給每個網域精確的紀錄值；下面是這些紀錄的形狀。

  • 郵件主機要有 A 與 AAAA。伺服器兩族都有就兩筆都加；會收信的每個網域都要有自己的 MX、SPF、DKIM 與 DMARC。
  • PTR 在 VPS 設定，不在你的 zone。把反解指到 smtp.example.com，收件方才能確認寄件主機。
  • 憑證要涵蓋用戶端會用的每個名字。通常是 apex 加上 smtp.、imap.、pop. 與網站網域。
  • 三種憑證流程。HTTP-01、DNS-01（手動或 Cloudflare token）與上傳；每個網域的憑證依 SNI 選擇，HTTP-01 與 Cloudflare 會自動續期。
@                  A/AAAA  203.0.113.10 / 2001:db8::10
mail               A/AAAA  同一個位址
smtp               A/AAAA  同一個位址
@                  MX      10 smtp.example.com.
@                  TXT     "v=spf1 a mx ~all"
default._domainkey TXT     "<安裝精靈產生的值>"
_dmarc             TXT     "v=DMARC1; p=quarantine; rua=mailto:postmaster@example.com"

傳播比精靈慢。先用 dig +short MX example.com、DKIM 的 TXT、_dmarc 與 dig -x <server-ip> 確認，再開始怪伺服器。

IPv4 與 IPv6 是兩個獨立決定

一個設定管監聽，一個管外送，主機只有單族時會自動降級。

  • listenMode：both、ipv4 或 ipv6。both 用 Go 的雙棧 wildcard，同一個 socket 服務兩族。
  • egressMode 決定外送族別。both 使用 Happy Eyeballs：只有 AAAA 的目的地走 IPv6，只有 A 的走 IPv4。
  • 啟動時偵測缺少的族別。設定的族在這台主機不存在，會記警告並改用另一族。
  • 健康檢查跟著同一結果。先試 127.0.0.1 再試 [::1]，IPv6-only 容器不會因為不聽 IPv4 被判定 unhealthy。
"listenMode": "both",
"egressMode": "both"

不靠猜測。安裝精靈的 A/AAAA 指引與公開位址偵測都分族別，IPv6 位址不會被當成 IPv4 印出來（反之亦然）。

不偷懶的郵件伺服器預設

密碼、TLS 與安裝精靈的曝光窗口，是最重要的三件事。

密碼與 session

PBKDF2-HMAC-SHA256、210,000 次迭代，密碼至少 8 字元；改密碼會撤銷所有現有 session。舊的 MD5 密碼會在下一次成功登入時升級。

TLS 不是選項

只支援 TLS 1.2／1.3，預設嚴格 SNI，IMAP 不會在沒有 TLS 的情況下暴露；外送時對方 MX 憑證驗不過就回報失敗，不會偷偷退回明文。

機密集中在一個地方

config/config.json 以 0600 寫入，DKIM 私鑰與 TLS 金鑰都在 config/。備份它、不要 commit、並且在對外之前完成安裝精靈。

常見問題

把 MX 指到新主機之前，值得先知道的事。

這是郵件伺服器，還是只有網頁信箱？

兩者都是。iMail 自己處理 SMTP、submission、SMTPS、IMAPS、POP3/STLS 與 POP3S，同時提供網頁信箱與管理台。任何標準郵件軟體都能連，網頁介面不是收發信的必需品。

VPS 擋 25 port，還能用嗎？

若供應商支援替代 port，收信可以；但要直接寄到其他郵件伺服器就需要 outbound TCP 25。請供應商解鎖，或自己接 relay；iMail 不會把被擋的 port 藏成一個普通的 timeout。

多網域時怎麼登入？

只有一個網域時，alice 與 alice@example.com 都可以。兩個網域以上必須用完整位址，因為裸名稱會有歧義。帳號是全域唯一：alice@one.example 與 alice@two.example 不能並存，請命名成 alice 與 alice-sales。

一定要用它申請的 ACME 憑證嗎？

不用。HTTP-01、手動 DNS-01、Cloudflare DNS-01 與上傳 PEM 都支援，可全域或每個網域分開。自動續期只適用兩種 ACME 流程；上傳的憑證要自己注意到期。

可以放在 TLS 反向代理後面嗎？

可以。把 httpsEnabled 設成 2（HTTP-only），讓代理終結 TLS。session cookie 只在 HTTPS 啟用時標 Secure，所以代理必須可信。

要備份什麼？

整個 config/：config.json、SQLite 資料庫（或你的 DSN）、DKIM 私鑰與憑證目錄。複製到新主機，伺服器就回到原本的樣子。

IPv6-only 或 IPv4-only 主機可以跑嗎？

可以。listenMode 與 egressMode 彼此獨立，啟動時發現設定的族別不存在會記警告並改用另一族；送到雙棧目的地時使用 Happy Eyeballs。

為什麼是 AGPL？

自架、fork、收費支援都可以。但如果你把修改過的 iMail 當成網路服務給別人用，使用者必須能取得你實際執行版本的原始碼——這就是第 13 條。

iMail 是給自己網域用的自架郵件伺服器：單一 Go binary、內嵌 Vue 3 前端， 執行時不需要任何外部服務。
